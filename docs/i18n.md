# Languages (i18n)

English is the base language and the fallback; Russian is the second one. A person's language comes from
Telegram's `language_code`; anything we do not ship falls back to English.

## Where the texts live

- Bot and server texts: `internal/i18n/locales/<lang>.json` (embedded into the binary), one flat file per language.
  Keys are dotted lowercase, grouped by prefix (`btn.back`, `app.name`). Values use Go verbs (`%s`, `%d`).
- Web app: `web/public/locales/<lang>/<namespace>.json` (`bot.json` for customers, `admin.json` for the operator
  screens). Nested keys, `{{placeholder}}` interpolation.
- Plurals: add a suffix to the key (`day_one`, `day_few`, `day_many`, `day_other`). English needs `_one` and
  `_other`; Russian needs `_one`, `_few`, `_many` and keeps `_other` beside them as the required fallback form.
  `_zero`/`_two` are understood only by the web app (i18next). The Go side (`plural.go`, `category`) returns just
  one/few/many/other, so a Go language that needs `_zero`/`_two` must first extend `category`.
- Texts built where the reader is not known (order titles, admin notes) are stored as a catalog key plus
  arguments (`i18n.M(...)`) and rendered in each reader's language.

## Wording

Short, warm, polite, no internal jargon. Use: Manage (not "admin panel"), support (not "administrator", for
customers), payment service (not "provider"), VPN panel, payment receipt, extras. Payment-service names and their
field names (Shop ID, API token, Crypto Pay) stay as the services call them. `TestNoJargon` catches the most common banned words (not the whole list).

## Adding a language (for example `de`)

1. Copy `internal/i18n/locales/en.json` to `de.json` and translate the values. Keep keys and format verbs.
2. If German needs more plural forms than English, add a case to `category` in `internal/i18n/plural.go`
   and add the matching key suffixes. Two-form languages need nothing.
3. Copy `web/public/locales/en/` to `web/public/locales/de/` (`bot.json`, `admin.json`) and translate.
4. In `web/src/main.tsx` add `import 'dayjs/locale/de'` and the number-format locale for it (the `setFormat`
   `locale` mapping, currently `ru` to `ru-RU`, otherwise `en-US`).
5. Add `'de'` to `supported` in `web/src/i18n.ts`.

## Checks

- `go test ./internal/i18n/` checks that every language has exactly the keys of English (plural forms included)
  with the same format verbs, and that no catalog contains banned jargon.
- `cd web && bun run check:locales` does the same for the web namespaces (keys and `{{placeholders}}`);
  `bun run build` runs it first.
