## Зачем

Клиентам VPN-сервиса не нужно писать в поддержку, чтобы узнать, когда заканчивается подписка, или чтобы её оплатить. Бот — это лаунчер: каждая кнопка его меню (Подписки, Баланс, Друзья, Тарифы, Платежи, Продлить) открывает WebApp на нужной странице. В самом боте остаётся онбординг (`/start`, ввод ссылки на подписку), чеки для ручных платежей, Telegram Stars, уведомления и карточки заказов для админов.

Один Go-процесс: бот (long polling) и HTTP-сервер для WebApp по пути `WEBAPP_PATH`. Все данные клиентов приходят из публичного API remna-control; собственная SQLite бота помнит только тех, от кого ждут ссылку на подписку, а также заказы и настройки.

## Возможности

- **Подписки и аддоны.** Статус, срок и трафик из панели, плюс тарифы, доступные для продления.
- **Баланс и история.** Пополнения и платежи, каждый применяется ровно один раз.
- **Рефералы.** Пригласительные ссылки и сколько приносит каждый приглашённый.
- **Оплата.** Telegram Stars, ЮKassa, CryptoBot, Heleket, PayPalych, Platega, ручной перевод с чеком и баланс. См. [Платёжные провайдеры](#платёжные-провайдеры).
- **Админка.** Заказы, способы оплаты и общие настройки — из WebApp, без перезапусков. См. [Админка](#админка).
- **Уведомления.** Предупреждения о трафике и напоминания об оплате.
- **Интерфейс на английском и русском** по языку Telegram. См. [docs/i18n.md](docs/i18n.md).

## Развёртывание

Положите `compose.yml` и `.env` рядом с панелью и выполните `docker compose up -d --build`. Контейнер подключается
к docker-сети панели; его Traefik-метки направляют `Host(APP_DOMAIN)` c `PathPrefix(WEBAPP_PATH)` или `PathPrefix(/pay/)` (вебхуки провайдеров) в бот
с более высоким приоритетом, чем у роутера панели. С другим балансировщиком направьте оба пути на порт 8090.

## Режимы доступа

Режим — это настройка в админке (см. [Админка](#админка)); по умолчанию `closed`.

- `open` — бота может запустить кто угодно; новый пользователь становится клиентом remna-control.
- `closed` — только клиенты, у которых в панели задан `telegram_id`, пользователи, приславшие ссылку
  на свою подписку (бот привязывает их Telegram id), и пришедшие по реферальной ссылке.

Реферальные ссылки выглядят как `https://t.me/<bot>?start=ref_<code>`; код выводится из id клиента
и `REF_SECRET`, ничего не хранится.

## Конфигурация

В переменных окружения только то, что нужно для запуска процесса. Всё остальное (режим бота, способы оплаты
и их ключи, уведомления) настраивается в админке и хранится в SQLite бота.

| Переменная | Обязательна | По умолчанию | Назначение |
|---|---|---|---|
| `BOT_TOKEN` | да | | токен Telegram-бота |
| `REMNACTL_URL` | да | | базовый URL remna-control, например `http://vpn-control:8080` |
| `REMNACTL_TOKEN` | да | | API-токен remna-control (см. ниже) |
| `PUBLIC_URL` | да | | публичный origin, например `https://control.example.com`; вебхуки провайдеров идут на `PUBLIC_URL/pay/<provider>`, поэтому нужен https и доступность снаружи |
| `WEBAPP_PATH` | нет | `/bot` | путь WebApp; URL WebApp = `PUBLIC_URL + WEBAPP_PATH` |
| `REF_SECRET` | да | | секрет реферальных кодов; из него же выводится ключ шифрования сохранённых платёжных данных. Смена делает недействительными все выданные ссылки, а ключи придётся ввести заново |
| `ADMIN_IDS` | да | | Telegram id админов через запятую (например `12345,67890`) |
| `HTTP_ADDR` | нет | `:8090` | адрес, который слушает сервер |
| `DB_PATH` | нет | `/data/bot.db` | SQLite бота (ожидаемые ссылки клиентов, заказы, настройки) |
| `LOG_LEVEL` | нет | `info` | `debug` / `info` / `warn` / `error` |

**Токен панели:** remna-control → Настройки → API-токены → пресет **Telegram bot**
(`customers:lookup`, `customers:get`, `customers:create`, `customers:update`, `customers:list`,
`subscriptions:list`, `tariffs:list`; два списка нужны для уведомлений, плюс платёжные права и
`stats:settings` (только чтение), который отдаёт базовую валюту).
Создавайте токен remna-control с пресетом *bot* (он включает платёжные права), старый токен нужно перевыпустить.
Токен, выпущенный до добавления `stats:settings` в пресет, тоже нужно перевыпустить; до этого бот использует
базовую валюту из админки (если она задана).

## Админка

Админы — это Telegram id из `ADMIN_IDS`. Права проверяются при каждом запросе.

- **Первый запуск:** все способы оплаты выключены, у общих настроек значения по умолчанию: режим `closed`, оплата с
  баланса `mixed`, проверка уведомлений раз в 60 минут, предупреждение о трафике при 80%, напоминания об оплате за 3 и 1 день
  до конца, неоплаченные заказы истекают через 48 часов, базовая валюта берётся из панели. Если при старте не включён ни один
  способ, админы получают одно личное сообщение о том, что способы оплаты не настроены.
- **Профиль бота:** при первом запуске, если у бота ещё нет описания, он сам заполняет название, описания
  (со ссылкой на этот репозиторий), команды, кнопку меню и фото. `/init` делает то же самое по запросу, перезаписывая
  то, что задано в @BotFather, и отвечает, какие шаги не удались. `/admin` и `/init` видны только в меню команд админов.
- **Открыть админку:** отправьте боту `/admin` (или нажмите кнопку на карточке заказа). В ней есть экраны
  заказов, способов оплаты и общих настроек.
- **Способы оплаты:** включите способ (перевод с чеком, ЮKassa, CryptoBot, Heleket, PayPalych, Platega,
  Telegram Stars), введите ключи и сохраните. URL вебхука для кабинета провайдера показан рядом с каждым провайдером.
  Кнопка «Проверить» тестирует ключи там, где провайдер это поддерживает (CryptoBot, ЮKassa). Изменения применяются
  сразу, без перезапуска; выключенный способ по-прежнему завершает уже выставленные счета.
- **Общие настройки:** режим бота, режим оплаты с баланса, запасная базовая валюта, интервал уведомлений (`0` выключает
  уведомления), процент предупреждения о трафике, дни напоминаний, срок жизни заказа.
- **Ключи зашифрованы** в базе бота ключом, выведенным из `REF_SECRET`. Если `REF_SECRET` меняется,
  сохранённые ключи нельзя прочитать (бот пишет предупреждение при старте), их нужно ввести заново.
- **Карточки заказов:** заказы, требующие решения (чек на проверку, платёж с неверной суммой), приходят личными
  сообщениями каждому админу из `ADMIN_IDS` с кнопкой, открывающей заказ в админке. Каждый админ должен один раз нажать
  `/start` в боте, иначе Telegram не даст боту ему писать (экран «Заказы» показывает, кому нельзя написать). Одобряйте или отклоняйте
  в приложении; карточки во всех чатах админов обновятся решением.

## Платёжные провайдеры

Клиенты могут платить через **Telegram Stars**, **ЮKassa** (карты, СБП), **CryptoBot** и **Heleket** (крипта), **PayPalych** и **Platega**, а также
ручным переводом и с баланса. Провайдер появляется на оплате, когда админ включил его и ввёл ключи. Платёж подтверждается
автоматически и применяется ровно один раз; платёж, пришедший по истёкшему или отменённому заказу, всё равно применяется,
а платёж с неверной суммой уходит админам карточкой.

Счета выставляются в базовой валюте панели. Провайдер, не поддерживающий эту валюту, отклоняет счёт,
и клиент видит «не удалось создать счёт». Stars пересчитываются по курсу из админки (единиц базовой валюты за Star).

Счета провайдеров требуют подтверждённой базовой валюты: либо панель отвечает (токен с `stats:settings`), либо
базовая валюта явно задана в общих настройках. Иначе бот пишет ошибку, а платежи через провайдеров остаются выключенными — ручная
оплата и баланс не затрагиваются.

Вебхуки: бот принимает `POST {PUBLIC_URL}/pay/yookassa`, `/pay/cryptobot`, `/pay/heleket`, `/pay/pal24`, `/pay/platega` (не под `WEBAPP_PATH`) —
направьте `/pay/*` на `HTTP_ADDR` бота в вашем обратном прокси и укажите URL в кабинете провайдера
(он показан рядом с каждым провайдером в админке; ЮKassa: HTTP-уведомления о `payment.succeeded`; CryptoBot: Crypto Pay → Мои приложения → Webhooks; Heleket шлёт на
callback URL, который бот передаёт с каждым счётом; PayPalych: укажите `{PUBLIC_URL}/pay/pal24` как **Result URL** в
кабинете PayPalych — подпись постбэка не покрывает статус, поэтому постбэк лишь предфильтр, а каждое
подтверждение проверяется по счёту (`bill/status`); постбэк без `bill_id` игнорируется, и платёж
подтверждается фоновой проверкой примерно через минуту; Platega: укажите `{PUBLIC_URL}/pay/platega` как **callback URL** в настройках
мерчанта Platega — она аутентифицируется заголовками `X-MerchantId`/`X-Secret`). Stars вебхука не требуют. Если вебхук потерян, бот
раз в минуту спрашивает провайдера об ожидающих счетах.

Проверка по каждому провайдеру (в тестовом режиме провайдера): ЮKassa — тестовый магазин и тестовая карта; CryptoBot — testnet через
@CryptoTestnetBot; Heleket — мерчант в тестовом режиме; PayPalych — создайте небольшой счёт, оплатите и проверьте статус *Оплачен*; Platega — то же с настроенным способом оплаты; Stars — оплатите небольшой заказ с тестового аккаунта. Создайте пополнение
на минимальную сумму, оплатите его и проверьте, что заказ стал *Оплачен*, в панели появился платёж с названием провайдера
в качестве способа, а повторная доставка вебхука ничего не меняет.

PayPalych и Platega написаны по эталону Bedolaga и не проверялись на живых сервисах.

## Разработка

Задачи запускаются через [Task](https://taskfile.dev) (`task --list`), как в remna-control.

1. `task init` — создаёт `.env`, ставит зависимости WebApp и копирует `../vpn-control/data/vpn-control.db`
   в `dev/panel-data/` (в git не попадает; `task panel:db` обновляет копию, `PANEL_DB` меняет источник).
   Заполните `.env`: `BOT_TOKEN`, `REF_SECRET`, `ADMIN_IDS`, `LOCAL_DOMAIN` — поддомен вашего домена, например
   `local.example.com`. Контейнер панели читает `../vpn-control/.env` (меняется через `PANEL_ENV`).
2. `task up` — создаёт сертификат mkcert для `LOCAL_DOMAIN` (ставит CA mkcert), проверяет
   `/etc/hosts` (добавьте `127.0.0.1 <LOCAL_DOMAIN>`, если попросит) и запускает traefik, панель и бота.
   - `https://<LOCAL_DOMAIN>/` — remna-control, `https://<LOCAL_DOMAIN>/bot/` — WebApp,
     http://localhost:8088 — дашборд traefik.
3. В панели создайте API-токен (пресет **Telegram bot**, либо отметьте права из списка выше, если
   образ панели старше пресета), впишите его в `REMNACTL_TOKEN` и снова выполните `task up`.
4. В @BotFather укажите Mini App / домен бота `LOCAL_DOMAIN`. Telegram Desktop на этой же
   машине доверяет CA mkcert и открывает WebApp из кнопки меню.

`task logs` показывает логи бота, `task down` останавливает стек, `task test` запускает Go-тесты и проверку типов WebApp.
`task dev` — панель и traefik в Docker, бот на хосте (общается с панелью через `https://<LOCAL_DOMAIN>`); контейнер
бота останавливается, и traefik направляет путь WebApp на бота на хосте. Ничего не нужно перезапускать или удалять в процессе работы:
изменения в Go пересобирают и перезапускают бота ([air](https://github.com/air-verse/air), `.air.toml`, сборка с `-tags dev`, чтобы не встраивать `web/dist`), изменения фронтенда
пересобирают `web/dist` (`web/scripts/watch.ts`), который бот отдаёт с диска (`WEB_DIR`), так что достаточно перезагрузить WebApp. `task dev:web:server` — отдельный
dev-сервер для браузера.

### Команды

Требования: Go 1.26, [Bun](https://bun.sh), [Task](https://taskfile.dev), Docker; [golangci-lint](https://golangci-lint.run) для `task lint`.

```bash
task init       # .env, зависимости фронтенда, локальная БД панели
task up         # локальный стек: traefik + панель + бот на https://LOCAL_DOMAIN
task dev        # панель в Docker, бот на хосте с hot reload
task build      # бинарник со встроенным WebApp -> bin/bot
task test       # Go-тесты, проверка типов фронтенда, проверка локалей
task lint       # tidy, fmt, vet, golangci-lint
task docker     # Docker-образ remna-control-bot:local
task snapshot   # локальная сборка goreleaser
```

Стек: Go, [go-telegram/bot](https://github.com/go-telegram/bot), Fiber, SQLite без CGO ([modernc.org/sqlite](https://modernc.org/sqlite)); WebApp — React 19, Mantine 9, react-router, TanStack Query и i18next, собирается Bun и встраивается в бинарник.

### Релизы

CI запускается на каждый push и pull request ([`test.yaml`](.github/workflows/test.yaml)): проверка типов и сборка фронтенда, `gofmt`, `go vet`, тесты, golangci-lint и проверка конфига релиза. Тег запускает релиз ([`release.yaml`](.github/workflows/release.yaml)): goreleaser собирает бинарники `linux/amd64` и `linux/arm64`, подписывает контрольные суммы через cosign, прикладывает SBOM и публикует GitHub-релиз, а Docker-образ уходит в `ghcr.io/lentryd/remna-control-bot`.

```bash
git tag v1.0.0 && git push origin v1.0.0
```
